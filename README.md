# 分布式采集调度引擎

面向大规模数据采集团队的分布式采集调度引擎。覆盖采集节点集群管理、任务分片调度、结果聚合归并、节点健康监控、采集流量均衡、断点续采恢复与全局采集看板的完整分布式采集链路。

这是一个前后端分离的管理平台：前端 Vue 3 + Vite + TypeScript，后端 FastAPI（Python）。
两边各自独立启动，前端 dev server 已关掉自动打开页面，启动后按终端打印的地址手工打开。

## 目录结构

```text
.
├── frontend/                 Vue 3 + Vite + TypeScript 前端
│   ├── src/views/            每个业务模块一个页面
│   ├── src/api/              统一请求封装
│   ├── src/stores/           会话与筛选状态
│   └── vite.config.ts        dev server 配置（open: false）
├── backend/                  FastAPI（Python） 后端
│   ├── app/routers/          每个业务模块一组接口
│   ├── app/services/         业务规则与状态流转（intervals.py 是范围统一口径）
│   ├── app/seed_coverage.py  分片覆盖准入的示例数据
│   └── app/store.py          内存数据仓库与示例数据
├── .gitignore
└── docker-compose.yml
```

## 启动

### 后端

```bash
cd backend
python3 -m venv .venv && .venv/bin/pip install -r requirements.txt
./run.sh
```

健康检查：`curl http://127.0.0.1:8000/api/health`

### 前端

```bash
cd frontend
npm install
npm run dev
```

前端默认监听 `http://127.0.0.1:5173/`，dev server 不会自动打开浏览器，
需要自己访问。`/api` 由 vite 代理到后端 `http://127.0.0.1:8000`。

## 分片覆盖准入核对

采集计划提交分片范围版本后，先经过覆盖准入核对，再同步给聚合侧：

- 范围统一按 `[起点, 终点)` 口径解析（兼容 `0-100`、`[0, 100)`、`100~200`、`开头-20`、`500-末尾`），
  覆盖连续性、范围重复与完整性都按同一口径判定。
- 每个分片只占用一个容量版本下的节点容量；同计划同范围重复提交只保留一份覆盖结果，
  并发提交只留一份覆盖结果。已确定的上限优先，后续提交不能另立一套阈值。
- 新旧范围版本同时到达且局部重叠时有两种处理顺序：
  - `补洞`：重叠处保留较窄范围，较宽的新范围只补进缺口，覆盖清单增加补洞条目，
    聚合待归并数随新增分片增加；
  - `整段替换`：新版本整段替换旧版本，覆盖清单只出现新版本分片，聚合待归并范围同步替换；
    容量装不下时替换不生效，原覆盖保留，新旧两个版本的来源都记录。
- 容量不足时保留未覆盖区间而不是静默启动；覆盖不完整的计划聚合侧看不到。
- 聚合只读取完整覆盖版本，按覆盖区间逐条建立待归并条目，重复建立不会生成第二个同范围任务；
  分片、聚合两个入口同步取用同一份准入汇总与覆盖清单。

接口：`/api/coverage`（汇总 / 准入）、`/api/coverage/entries`（清单）、
`/api/coverage/snapshot`（结论快照）、`/api/merge/coverage`、`/api/merge/pending/build`、
`/api/shard/coverage`。

规则测试：`cd backend && PYTHONPATH=.venv python3 -m unittest discover -s tests`，
覆盖范围解析、补洞与整段替换两种处理顺序、容量不足、重复提交与并发分配。

## 约定

- 每个模块的前端页面在 `frontend/src/views/<模块>/index.vue`，后端接口在
  `backend/app/routers/<模块>.py`，业务规则在 `backend/app/services/<模块>.py`。
- 列表接口统一返回 `{ items, total, page, size }`，动作接口统一返回 `{ ok, message }`。
- 状态流转只允许在 `app/services` 里改，路由层不做业务判断。
